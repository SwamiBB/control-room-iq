# Control Room IQ

**An AI operator for the live production control room.**
Built for the Microsoft × Premier League *Inside the Game* Developer Hackathon (October 2026).

Control Room IQ watches a live stream of synthetic football match events, turns them into live
statistics and tactical context, explains *why* a moment matters, proposes what should go on screen
next, and routes every on-air decision through a human operator before it reaches the overlay feed.
The same intelligence is personalized for an analyst, a casual fan, and an accessibility (audio
description) mode, in English, Spanish, Hindi, and Arabic.

> Football is the hackathon's domain. The architecture is a control room story: any environment that
> must turn a live event stream into explainable, auditable operator decisions.

## What it does (the five-stage pipeline)

| Stage | What happens | Where |
| --- | --- | --- |
| Ingest | Synthetic match events (passes, shots, tackles, pressure, possession) stream in at match speed or faster | `services/simulator` → Azure Event Hubs |
| Interpret | Events become match state and statistics: xG, pass networks, pressure index, momentum, player speed/distance thresholds | `services/ingest` on Azure Container Apps, state in Cosmos DB |
| Explain | A tactical explainer agent says why a moment matters (control vs. chaos, pressure shifts, rhythm) with citations to the underlying events | `services/agents` on Microsoft Foundry |
| Render | A studio producer agent proposes the next graphic and on-air line; an operator approves, holds, or overrides; approved items go out as a timed, machine-readable overlay feed | `services/api` + `web` operator console |
| Personalize | The narrator and personalizer agents produce analyst, fan, and accessibility variants in EN/ES/HI/AR | `services/agents` + `web` viewer |

Every narrative is scored for **faithfulness** against the ground-truth event stream using Foundry
evaluations, and every producer decision is logged with its reasoning.

## Microsoft and Azure technologies

Microsoft Foundry (Agent Framework, Foundry Agent Service, model router, evaluations, tracing,
content safety), Azure Event Hubs, Azure Container Apps, Azure Cosmos DB, Azure Logic Apps (approval
workflow), Azure AI Speech (audio description), Azure Monitor / Application Insights, Bicep + Azure
Developer CLI (`azd`), GitHub Actions, GitHub Copilot agent mode.

## Quick start (local, no Azure required)

```powershell
# Windows PowerShell (Python 3.11+; tested on 3.13)
python -m venv .venv; .\.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
$env:CRQ_OFFLINE = "1"
pytest                                          # all tests, no Azure
python -m simulator.cli reference               # regenerate the three reference matches in data/
python -m api.offline                           # play the reference match through the full pipeline
uvicorn api.main:app --reload                   # then GET /api/replay?seed=42&speed=1
```

## Synthetic data

All match data is generated by the simulator from fictional clubs (`data/clubs.json`) and scripted
storylines (`data/storyline*.json`). The same seed always produces a byte-identical file.

| Seed | Match | Story | Files |
| --- | --- | --- | --- |
| 42 | Harbor City v Northfield United | Big chance 23', foul and yellow 31', pressure build, hero scene 41' (save, then rebound goal), late chance 78'; 1–0 | `reference_match.jsonl`, `reference_tracking.jsonl.gz` |
| 7 | Riverside Athletic v Ironbridge FC | Offside, penalty, straight red, ten men equalise; 1–1 | `reference_match_m2.jsonl`, `reference_tracking_m2.jsonl.gz` |
| 101 | Northfield United v Harbor City | 0–2 to 2–2 comeback with a second yellow | `reference_match_m3.jsonl`, `reference_tracking_m3.jsonl.gz` |

Events follow an Opta-style shape with kloppy event names, plus our extensions (`shot_taken` before every
shot result, `stoppage`, `whistle`, `crowd` at 2 Hz). Tracking is ball plus 22 players at 4 Hz. Realism is
checked over 200 seeded matches in [docs/CALIBRATION.md](docs/CALIBRATION.md) (11 of 11 checks in range).
Contracts: [docs/SCHEMA_CHANGES.md](docs/SCHEMA_CHANGES.md); example records: `packages/schemas/fixtures/`.

## Replay API (the demo's play button)

The replay is a feed, not a file: each event is delivered 1–3 s after the action (seeded drift) and a
shot's strike always arrives before its result.

| Endpoint | Does |
| --- | --- |
| `GET /api/replay?seed=42&speed=1` | Start (or restart) a reference match: 42, 7 or 101 |
| `POST /api/replay/pause`, `POST /api/replay/resume` | Pause and resume the match clock |
| `POST /api/replay/speed?x=2` | Change playback speed |
| `POST /api/replay/jump?minute=41&second=12` | Jump to a match minute (state is refolded; the hero scene is at 41:12) |
| `GET /api/replay/status` | Current clock, position and speed |
| `GET /api/screen` | ScreenState from the layer scheduler: on air, queued, held |
| `POST /proposals/{id}/approve`, `/hold`, `/override` | Operator decisions; override needs `override_line` |
| `GET /api/decisions`, `GET /api/decisions.csv` | The audit trail: one row per state transition (operator, SLA, supersession) |
| `GET /api/evaluations`, `GET /api/evaluations.jsonl` | One row per agent output (snapshot, output, cites, source, routed model, latency, decision); JSONL as query / context / response for Foundry evaluations |

Offline, the same rows come from `python -m api.offline --eval-out evaluations.jsonl`.

**Mandatory gate.** Nothing airs without an operator's approve or override; there is no auto-approve path
and no setting that adds one. A proposal untouched for 20 s is moved to `sla_held` (logged as a decision by
actor `sla`); a goal or card on the same phase or stoppage supersedes a pending lower-priority proposal
(actor `supersession`). The state machine is in `services/api/api/gate.py`.

Operators receive `feed`, `state`, `moment`, `proposal`, `decision`, `screen` and `cue` messages on `/ws/operator`. Viewers on
`/ws/viewer` receive `cue` (the strike: `{team, direction, crowd_level, clock}`, sent the moment a shot is
struck, with no model and no operator in the path, under 1 s) and `overlay` (only after an operator decision).

With Azure credentials (`az login`) and `.env` filled from `.env.example`, the same commands
stream to Event Hubs and the agents run on Foundry. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)
for the resource list and [docs/SETUP.md](docs/SETUP.md) for provisioning with `azd up`.
